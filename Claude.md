# 4DHOI: Zero-Shot 4D Human-Object Interaction via Part Affordance Guidance

## One-Line Summary

4DHOI is a zero-shot, modular pipeline that generates realistic 4D human-object interactions from text prompts by first constructing a Part Affordance Graph (PAG) via an LLM, generating a video of the interaction, and then reconstructing and jointly refining the 3D geometry and motion of both humans and objects across the full sequence using foundation models and physics-aware optimization.

---

## Core Idea: Part Affordance Graph (PAG)

The intellectual backbone of 4DHOI is the **Part Affordance Graph (PAG)** -- a structured semantic graph that explicitly encodes *who touches what, where, when, and how* during a human-object interaction.

### PAG Structure

A PAG is a bipartite graph with three components:

1. **Object Part Nodes**: Semantic decomposition of each object into functional parts (e.g., "iron, handle", "iron, soleplate", "ironing board, surface").

2. **Body Part Nodes**: 12 human body parts -- left/right variants of hand, arm, shoulder, leg, foot, plus head and hips.

3. **Interaction Edges**: Each edge connects an object part to a body part and carries two boolean attributes:
   - `is_continuous`: Does physical contact persist throughout the interaction?
   - `is_rel_static`: Do the two parts remain relatively stationary with respect to each other during contact?

4. **Object States**: Per-object motion properties:
   - `is_translational`: Does the object undergo global translation?
   - `is_rotational`: Does the object rotate?

### Why PAG Matters

PAG serves as the **central representation** that flows through the entire pipeline:
- **Video generation**: PAG produces a 150-word interaction description that guides the video diffusion model.
- **Segmentation**: PAG node names tell the segmenter which entities and parts to detect.
- **Object mesh part segmentation**: PAG part names guide 3D mesh segmentation.
- **Joint refinement**: PAG edges directly supervise contact constraints. Object states control smoothness loss behavior. `is_continuous` and `is_rel_static` determine contact loss scheduling.

### PAG Generation

PAGs are generated by prompting an LLM (Claude, DeepSeek-R1, etc.) with a detailed 320-line system prompt containing rules for:
- Part segmentation granularity
- Body part naming conventions
- Contact vs. proximity distinction
- State attribute inference from motion type

A **multi-sample voting mechanism** ensures robustness: multiple LLM samples are generated, node names are normalized, and majority voting determines the final edges and attributes.

The pipeline consists of **17 stages** organized into three phases:

## Joint Human-Object Refinement (Core Optimization)

This is the most technically sophisticated stage (~1086 lines of loss code). It jointly optimizes:

### Optimization Variables
- **Per-frame human global SE(3) deltas**: Corrections to the aligned human motion
- **Per-frame object SE(3) deltas**: Corrections on top of CoTracker-tracked poses
- **One global uniform scale per object**: Bounded log-scale parameterization

### Loss Functions (10 terms)

#### 1. Tracking Loss (weight: 20.0, fixed)
Anchors object deltas to initially tracked poses, preventing drift from CoTracker.

#### 2. Object 2D Chamfer Loss (scheduled)
Bidirectional Chamfer distance between projected object surface points and 2D mask pixels. Uses Geman-McClure robust weighting.

#### 3. Object Part 2D Chamfer Loss (scheduled)
Same as above but per-semantic-part, using triangle-level part labels.

#### 4. Translation Smoothness Loss (scheduled)
- If `is_translational = true`: L2 midpoint smoothness
- If `is_translational = false`: Static penalty (10x stronger) forcing near-zero motion

#### 5. Rotation Smoothness Loss (scheduled)
- If `is_rotational = true`: SLERP-based geodesic smoothness
- If `is_rotational = false`: Static penalty forcing near-zero rotation

#### 6. Scale Loss (scheduled)
ReLU on |log(scale) - 1| - 0.1. Only active when `--optimize_object_scale=true`.

#### 7. SDF-Based Penetration Loss (scheduled: 0 -> 10.0, ramped)
Pre-computes 128^3 SDF grids in each object's canonical frame. Queries SDF for human vertices transformed into object space. Penalizes negative SDF values (inside the object). Gradually increased to avoid early optimization instability.

#### 8. No-Contact Loss (scheduled)
Enforces separation between body parts and object parts that do NOT have PAG edges.

#### 9. Contact Drift Loss (scheduled: 10.0 -> 1e3, ramped)
Minimizes distance between body parts and object parts connected by PAG edges. Uses different reduction strategies:
- **"mean" reduction** for hands and feet (larger contact surfaces)
- **"min" reduction** for other body parts (point-like contact)
Handles left/right body part deduplication.

#### 10. Total Loss
Sum of all weighted terms with per-frame diagnostics and CSV/plot export.

### Optimization Hyperparameters

| Parameter | Value |
|-----------|-------|
| Optimizer | Adam |
| Learning Rate | 1e-3 |
| Iterations | 5000 |
| Early Stopping Start | Iteration 500 |

## Coordinate System & Representations

### Coordinate Frames
- **Camera Frame (OpenCV convention)**: X-right, Y-down, Z-forward
- **PyTorch3D convention**: Flipped signs, handled via `F_P3D_TO_CV` matrix
- **Canonical Frame**: Per-object local coordinates for SDF queries

### Human Representation
- SMPL body model with 6890 fixed-topology vertices
- Per-frame PLY files with vertex positions
- Part segmentation via `smpl_vert_segmentation.json` mapping body part names to vertex indices

### Object Representation
- Template mesh (vertices + faces) in canonical space
- Per-frame SE(3) transforms (4x4 matrices) from tracked + refined poses
- Optional per-object uniform scale
- Triangle-level semantic part labels

### Tracking Data
- Packed 2D point clouds with per-frame length arrays
- Area-weighted surface sampling for Chamfer computation

## Key Design Decisions

1. **Zero-shot via foundation models**: No training data required for new interactions. Generalization comes from combining pretrained models rather than learning on interaction datasets.

2. **PAG as central representation**: The graph bridges language understanding (LLM) with geometric optimization (contact constraints). This is the primary novelty.

3. **Video as intermediate representation**: Rather than directly generating 3D motion (like diffusion-based methods), 4DHOI generates video first, then reconstructs 3D. This leverages the superior quality of current video generation models.

4. **Modular pipeline**: Each stage is independent, allowing component upgrades without touching the rest. Different stages use different conda environments.

5. **Rigid object assumption**: Objects are represented as rigid meshes with SE(3) transforms. No articulation, deformation, or topology changes.

6. **Optimization-based refinement**: The final stage uses classical optimization (Adam) rather than learned refinement. This is principled but slow.

---

## Limitations

1. **Rigid objects only**: Cannot handle articulated objects (drawers, scissors, laptops) or deformable objects (cloth, rope).
2. **Depends on video quality**: The entire 3D reconstruction is bounded by the quality of the generated video.
3. **No physics simulation**: Uses SDF penetration as a proxy for physics but lacks force modeling, gravity, friction, momentum.
4. **Coarse hand modeling**: SMPL has low hand resolution (6890 total vertices). Finger-level grasping accuracy is limited.
5. **Sequential pipeline**: Errors compound across stages with no backward correction mechanism.
6. **Single viewpoint**: Generated video is from a single camera view, creating depth ambiguity.
7. **Optimization speed**: Joint refinement takes thousands of iterations per sequence.
8. **No learned priors on interaction dynamics**: Contact constraints come from LLM reasoning, not learned motion distributions.
