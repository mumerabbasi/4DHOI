# Plan: First-Frame SMPL-X Human-Scene Grounding

## Goal

Build a first-frame human-scene grounding stage for `4DHSI` that starts from the already good interaction generated by the `4DHOI`-style pipeline, then optimizes the human into the real scene so that:

- the human remains faithful to the generated interaction,
- the intended body parts contact the intended scene object parts,
- the feet are supported by the floor,
- the body does not penetrate scene geometry,
- the pose stays realistic and close to the original `GVHMR` estimate.

This stage is only for frame 0. Motion can be added later after the first-frame objective is stable.

## Core Idea

Do **not** optimize mesh vertices directly. Optimize a **GenZI-inspired but stronger SMPL-X parameter set** initialized from `GVHMR` frame 0:

- `transl`
- `global_orient`
- `body_pose`
- `global_scale`

For now, do **not** optimize:

- `left_hand_pose`
- `right_hand_pose`
- face / jaw / expression
- per-vertex offsets

The key improvement over the current rigid-only grounding is:

- keep the strong semantic contact supervision from `4DHOI` / `PAG`,
- borrow the human-prior and collision logic from `GenZI`,
- optimize a full articulated SMPL-X body instead of only root translation/scale.
- unlike GenZI, do **not** use `VPoser`; instead rely on `GVHMR` initialization plus explicit regularization.

## What To Reuse From Existing Work

### Reuse from `4DHOI`

- `Generate_PAG/`
  - use PAG contact semantics as the main supervision signal
- `Estimate_Human_Motion/`
  - use the SMPL-X human initialized from `GVHMR`
- `Estimate_Human_Motion/assets/smplx_vert_segmentation.json`
  - use body-part contact regions, including `left_hand_inner` and `right_hand_inner`
- `Track_Human_Object_Mesh`
  - reuse the semantic `intersect` / `nocontact` formulation style
  - reuse the notion of continuous vs non-continuous contact
  - later, reuse `contact_drift` once motion is introduced

### Reuse from `GenZI`

- optimize SMPL-X parameters, not only rigid transforms
- use strong human priors so optimization does not drift into implausible poses
- add explicit:
  - angle prior
  - self-intersection penalty
  - penetration/contact pairing
  - shape regularization

## Why This Should Beat GenZI

`GenZI` solves a weaker problem:

- no known target object semantics
- no PAG contact graph
- no `GVHMR` initialization
- no direct first-frame interaction estimate from our generated video

Our method should be stronger because we already know:

- which scene object is the target,
- which human body parts should be contacting it,
- a good first-frame human estimate from `GVHMR`,
- the generated image/mask/depth evidence for that same frame.

So the right strategy is:

- keep `GenZI`'s stabilizing priors,
- replace its generic scene-contact logic with our semantic PAG contact logic.

## Current Findings

- Disabling the global `scene_intersect` loss solved the head/neck rotation artifact. The current scene-global SDF is not reliable enough for the full room mesh, so this loss needs a better formulation before it should be used again.
- The optimizer should prioritize moving the whole human toward the object before allowing large articulation changes. A staged root-first phase would likely make the interaction more natural because the hands can reach the contact region through body translation first, instead of overextending one arm.
- `betas` are now frozen to the `GVHMR` estimate. First-frame grounding should adjust placement and pose, not person identity/body shape.

Do **not** optimize:

- `left_hand_pose`
- `right_hand_pose`
- face / jaw / expression
- per-vertex offsets

### Recommended representation

Our approach is intentionally different from GenZI here:

- GenZI uses `VPoser` and optimizes a low-dimensional latent body-pose code
- our first implementation should **not** depend on `VPoser`
- instead, optimize SMPL-X pose parameters directly and regularize them strongly to the `GVHMR` initialization

Recommended implementation:

1. optimize `global_orient` in a continuous 6D rotation representation
2. optimize `body_pose` directly
3. keep `betas` fixed to the `GVHMR` estimate
4. optimize a single scalar `global_scale`
5. convert optimized pose parameters to the SMPL-X forward representation each iteration

Practical note:

- GenZI also does not optimize detailed hand articulation in the way we would need for fine contact
- for our v1, keeping hand pose fixed is safer and simpler
- a later version can unlock hand pose once the body-grounding objective is stable

## Initialization

### Base initialization

- initialize all SMPL-X variables from `GVHMR` frame 0
- initialize `global_scale = 1.0`
- transform the initialized human into the scene world using the current `align_human_to_scene.py` world-frame logic
- keep this as the reference pose `x_gvhmr`

### Important rule

The new optimization should **not** start from scratch. It should always start from the `GVHMR` solution and refine around it.

## Recommended Optimization Strategy

Even though this is a single frame, it should still be optimized in phases.

### Phase 1: root stabilization

Optimize only:

- `transl`
- `global_orient`
- `global_scale`

Keep:

- strong mask/root anchoring
- strong root regularization to `GVHMR`
- semantic contact losses on but not too aggressive

Purpose:

- place the human near the correct scene support/object region before changing articulation
- prefer whole-body translation toward the object before spending arm, neck, or spine degrees of freedom

### Phase 2: full-body scene fitting

Unlock:

- `body_pose`

Keep strong:

- `GVHMR` pose prior
- angle prior
- self-intersection prior
- scale prior

Increase:

- object contact
- floor contact
- scene penetration

Purpose:

- adapt knees, hips, elbows, shoulders, and spine so the human can actually fit the scene geometry
- keep palm placement improving through wrist/arm/body changes first

## Loss Design

The total loss should look like:

`L = L_image + L_scene_contact + L_scene_penetration + L_gvhmr_anchor + L_human_prior`

### 1. Image / observation anchors

These are weak anchors, not the main objective.

#### `L_mask`

- silhouette consistency with the generated first-frame human mask
- keeps the optimized human from drifting too far from the visible person

#### Optional `L_joints2d`

- 2D joint reprojection loss to first-frame keypoints
- use either `GVHMR` 2D joints or a detector such as `VitPose`
- especially useful once `body_pose` is unlocked

### 2. Semantic scene-contact losses

These are the main improvement over `GenZI`.

#### `L_obj_nocontact`

For each PAG contact edge:

- use the scene target object part as the fixed geometry
- use the corresponding SMPL-X body segment as the moving geometry
- use `left_hand_inner` / `right_hand_inner` for hands
- use `min` or `mean` reduction depending on PAG contact type

This should be **semantic**, not scene-global.

#### `L_obj_intersect`

Penalize penetration between the same contact-driving human parts and the target object SDF.

#### Conditional contact logic

Borrow the important idea from `GenZI`:

- if a contact region is intersecting the object, prioritize `intersect`
- if it is not intersecting, prioritize `nocontact`

This avoids pushing contact attraction and penetration simultaneously in a conflicting way.

### 3. Floor support losses

The feet need separate treatment from generic object contact.

#### `L_floor_intersect`

- penalize foot support vertices below the floor

#### `L_floor_nocontact`

- encourage feet to stay close to the floor support surface

#### Important change

Do **not** use the whole foot for floor contact.

Add dedicated SMPL-X segments:

- `left_foot_support`
- `right_foot_support`

These should be the sole / support region only.

### 4. GVHMR anchoring losses

These keep the optimized result close to the already good first-frame interaction.

#### `L_root_gvhmr`

- regularize `transl` and `global_orient` to the `GVHMR` initialization

#### `L_pose_gvhmr`

- regularize `body_pose` to the `GVHMR` initialization
- this should be one of the strongest terms early on

Recommended variants:

- direct parameter-space L2 on body pose
- or 3D joint-space loss to initial joints
- or vertex-space loss on non-contact body regions

This is the clean analogue of GenZI's optional `joints3d_init` stabilization term, except here the reference should be the `GVHMR` frame-0 human rather than a previous GenZI checkpoint.

A practical hybrid is:

- joint-space loss for the whole body
- stronger contact-region freedom
- weaker regularization on limbs expected to adapt to the scene

#### `L_shape_gvhmr`

- `betas` are currently frozen to the original `GVHMR` betas
- keep this as the default unless there is a clear identity/scale mismatch that cannot be solved by root pose or global scale

#### `L_scale_prior`

- regularize the global human scale to `1.0`
- keep this term strong enough that scale only absorbs real scene/camera mismatch, not pose/contact errors

Equation:

- `L_scale_prior = (log s)^2`

where:

- `s` is the global human scale

### 5. Human realism priors inspired by `GenZI`

Important difference from GenZI:

- GenZI uses `VPoser` as an extra pretrained pose-prior model and optimizes a latent body-pose code
- our first implementation should **not** use `VPoser`
- instead, we should rely on:
  - `GVHMR` pose anchoring
  - explicit angle prior
  - self-intersection penalty
  - beta regularization

This keeps the system simpler and avoids introducing an extra pretrained dependency in v1.

#### `L_angle`

- explicit angle prior to penalize implausible joint bends
- this is one of the most important pieces to borrow from `GenZI`

Summary:

- GenZI uses a hand-designed anatomical prior on selected body-pose coordinates
- some joint axes are only penalized when they bend in the anatomically wrong direction
- some other axes are encouraged to stay near zero

Equation:

- `L_angle = mean( { ReLU(s_i * theta_i) }_(i in C) union { |theta_j| }_(j in Z) )`

where:

- `theta` is the decoded SMPL-X body pose
- `C` is the set of signed joint-axis constraints
- `s_i in {+1, -1}` encodes which bending direction is implausible
- `Z` is the set of joint axes that should stay close to zero

Intuition:

- this stops the optimizer from solving contact by making elbows, knees, spine, or shoulders bend in unnatural directions
- for the first implementation, this should be the same prior as GenZI

#### `L_self_intersect`

- self-collision penalty for body-body penetration

This matters more once knees, elbows, and torso are free to move.

Summary:

- GenZI detects colliding triangle pairs on the SMPL-X mesh
- it then penalizes the amount of mesh penetration for those collisions

Equation:

- `L_self_intersect = 0`, if there are no colliding triangle pairs
- otherwise, `L_self_intersect = (1 / |P|) * sum_((f,g) in P) DFP(f, g)`

where:

- `P` is the set of colliding triangle pairs from BVH collision detection
- `DFP` is the distance-field penetration loss used by GenZI

Intuition:

- this prevents the body from intersecting itself, e.g. arm through torso, calf through thigh, or hand through leg
- for the first implementation, this should also be the same formulation as GenZI

#### `L_betas`

- `betas` control body shape rather than pose
- without a prior, the optimizer can cheat by changing body proportions instead of solving the actual grounding problem

GenZI formulation:

- `L_betas^GenZI = mean( (w ⊙ beta)^2 )`

where:

- `w` is all ones except the first shape coefficient has a larger weight
- this pulls body shape toward the neutral mean shape

Our formulation:

- `L_betas^ours = mean( (beta - beta_GVHMR)^2 )`

Optional stronger variant:

- `L_betas^ours = mean( (w ⊙ (beta - beta_GVHMR))^2 )`

Intuition:

- GenZI regularizes toward zero because it does not have a strong person-specific shape estimate
- we do have `GVHMR`, so we should regularize toward `beta_GVHMR` instead of toward the neutral body shape
- this keeps the optimized person looking like the same person while still allowing small shape corrections if needed

### 6. Optional scene-global safety loss

#### `L_scene_intersect_global`

- weak penalty for penetration of the body with any non-target scene geometry

Current finding:

- the existing full-scene SDF version should stay disabled for now
- it incorrectly treats much of the human, including the head/neck, as inside the scene
- this is likely because the ScanNet room mesh is not a clean watertight collision object

Replacement direction:

- restrict scene collision to meaningful surfaces and body parts
- use floor/object/wall-specific losses rather than one global signed SDF
- consider unsigned distance or local closest-surface constraints for non-watertight scene geometry

## Suggested Weighting Philosophy

### Early phase

High:

- `L_root_gvhmr`
- `L_pose_gvhmr`
- `L_scale_prior`
- `L_mask`

Medium:

- `L_obj_intersect`
- `L_floor_intersect`

Low to medium:

- `L_obj_nocontact`
- `L_floor_nocontact`

### Later phase

Keep high:

- `L_pose_gvhmr`
- `L_angle`
- `L_self_intersect`

Increase:

- `L_obj_nocontact`
- `L_floor_nocontact`
- `L_obj_intersect`
- `L_floor_intersect`

Lower but do not remove:

- `L_mask`

## Concrete Repo Plan

### A. Add a dedicated SMPL-X optimization module

Create a new module under `4DHSI/Align_Human_To_Scene/` for SMPL-X fitting, rather than overloading the current rigid-only script further.

Suggested split:

- `smplx_human_optimizer.py`
  - SMPL-X parameter container
  - forward pass to vertices/joints
- `smplx_scene_losses.py`
  - contact, penetration, priors, anchors
- `align_human_to_scene.py`
  - orchestration, loading, visualization, export

### B. Keep the current rigid aligner as initialization

Use the existing `align_human_to_scene.py` behavior to produce:

- a good root translation/orientation initialization
- first-pass scene/world alignment

Then feed that result into the new articulated optimizer.

### C. Extend the SMPL-X segmentation asset

Update `Estimate_Human_Motion/assets/smplx_vert_segmentation.json` with:

- `left_foot_support`
- `right_foot_support`

Keep using:

- `left_hand_inner`
- `right_hand_inner`

### D. Add a GVHMR parameter loader for frame 0

Load and cache for frame 0:

- `transl`
- `global_orient`
- `body_pose`
- `betas`

These become both:

- initialization
- regularization targets

For `betas`, the cached value is the fixed shape used by the optimizer.

### E. Reuse GenZI regularization selectively

Wire in:

- the same explicit angle prior
- the same self-intersection penalty
- the same style of shape regularization

Do **not** wire in for v1:

- `VPoser`
- latent-pose optimization

Instead add:

- `GVHMR` body-pose anchoring
- global-scale prior

The easiest reference implementation is the original `hms/human.py` and `GenZI`'s loss structure.

## Extension to Motion Later

Once frame 0 works, extend to the whole sequence by adding:

- temporal smoothness on `transl`, `global_orient`, and `body_pose`
- contact drift loss from `4DHOI`
- phase-aware PAG contact schedules
- optional object motion refinement if manipulated scene objects move

The sequence version should still be built on the same principles:

- `GVHMR` initialization
- semantic PAG contacts
- `GenZI`-inspired human priors without `VPoser`
- scene-aware penetration/support losses

## Recommended First Implementation

The first implementation should be intentionally narrow:

1. optimize exactly these SMPL-X variables:
   - `transl`
   - `global_orient`
   - `body_pose`
   - `global_scale`
2. keep these components frozen:
   - `left_hand_pose`
   - `right_hand_pose`
   - `betas`
   - face / jaw / expression remain frozen
   - no per-vertex offsets
3. use losses:
   - `mask`
   - `obj_intersect`
   - `obj_nocontact`
   - `floor_intersect`
   - `floor_nocontact`
   - `pose_gvhmr`
   - `root_gvhmr`
   - `scale_prior`
   - `angle`
   - `self_intersect`
4. do **not** use `VPoser` in v1
5. use direct SMPL-X pose optimization with strong `GVHMR` anchoring
6. test only on a few seated / leaning / hand-contact examples first

This is the most direct path to improving on `GenZI` with the strengths that already exist in `4DHOI`.
